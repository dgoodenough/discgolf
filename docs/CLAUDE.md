# docs/ — the site

Vanilla ES modules, no build step, no framework, no dependencies. What is in
this directory is what GitHub Pages serves. Edit a file, reload, done.

`index.html` loads `app.js` as `<script type="module">` and preloads the whole
import graph. `how-it-works.html` is a standalone page with no JavaScript of
its own.

## Modules

`app.js` is the entry point and owns the shell — page header, freshness flag,
tab wiring. Everything else lives in `js/`:

| module | owns |
|---|---|
| `core.js` | `state`, the `$` helper, every display formatter, `loadDiv` |
| `tooltip.js` | the scrub `probe()` and the `data-tip` marks |
| `cells.js` | the shared render layer: sparklines, links, counting caps, the live-event window |
| `sim.js` | the client-side Monte Carlo (cutline replay, per-event points draws) |
| `movers.js` | the biggest-movers panel |
| `forecast.js` | the standings table, column guide, expanded row, what-if |
| `possible.js` | the five "what's left" panels |
| `race.js` | the event-odds chart and table |
| `projection.js` | the two experimental tabs (2027, EuroTour) |

**The import graph is layered and must stay acyclic.** `core` imports nothing;
each layer only reaches downward:

```
core <- tooltip <- cells <- sim <- movers <- {forecast, possible, race, projection} <- app
```

A helper earns a place in `core` or `cells` once a *second* module needs it.
One with a single caller stays next to that caller — that is why `monthDay`
and `pendingWaves` sit in `cells` (only `playoffNote` uses them) rather than in
`core`.

Adding a module means adding a `<link rel="modulepreload">` to `index.html`, or
its fetch waits an extra round trip behind whatever imports it.

## Conventions that are load-bearing

- **Every explanation must work without a mouse.** A bare `title` attribute
  never fires on touch, and this site is read on phones. Use `tipAttrs(text)`
  for an inline mark (it emits the `title` *and* the `data-tip`), and
  `probe(el, resolve)` for anything scrubbable. The one exception is a sortable
  column header, which keeps a bare `title` because tapping it has to sort —
  its copy is surfaced through the column guide instead.
- **PDGA attribution is required, not decorative.** Player names link to the
  PDGA profile and event names to the PDGA event page —
  `playerLink()` and `eventLink()` in `cells.js`. This is a condition of the
  developer program (pdga.com/dev/developer-program); do not render a bare
  name where a link belongs.
- **Colour carries meaning, greyscale carries structure.** The palette is
  Ledger (`tokens.css`, vendored from github.com/dgoodenough/style — pin a
  copy, don't edit it in place): green = positive/have/happened, red =
  negative/missing/never, yellow = pending/upcoming. `probClass()` is the one
  place that maps a probability onto that scale.
- **Responsive columns drop by tier, not by breakpoint.** A column declares
  `hide: "t1"`…`"t4"` and `style.css` hides `t4` first (≤940px) through `t1`
  last (≤560px). Core columns declare no tier and never hide. The "All
  columns" toggle overrides the lot via `.cols-all`.
- The page must not scroll horizontally at phone width. Wide tables and charts
  each go in their own `.pv-scroll` container.

## Data

`docs/data/` is **gitignored** — it is generated by `dgpt/export.py` and
published to the `site` branch. A fresh checkout has the pages and no bundle,
so the site will render empty until you fetch one.

To work against real data locally:

```
git fetch origin site
git restore --source=origin/site --worktree -- docs/data
python3 -m http.server 8099 --directory docs
```

ES modules will not load over `file://`, so a server is required — opening
`index.html` directly will fail.

Bundle fields come from `dgpt/export.py`; that file is the schema. Code
defensively against older bundles where a field may be missing — the site is
served from the last published bundle, which can predate a field by a refresh
cycle. There are several existing fallbacks of this shape (`liveThru`,
`liveEvents`, the movers back-compat branch); follow them rather than assuming
a field is there.
